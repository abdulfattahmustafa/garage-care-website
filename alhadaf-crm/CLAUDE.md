# CLAUDE.md — alhadaf-crm

نظام إدارة علاقات عملاء (CRM) لمعرض سيارات "الهدف الأميز" (جدة، KSA)، بُني تلبيةً لبرومبت `CRM_PROMPT.md` الأصلي ومرتبط بمتطلبات معيار "إدارة علاقات العملاء" (10%) ضمن برنامج جميل بلس 2026 من عبداللطيف جميل موتورز.

## التقنيات المستخدمة ولماذا

- **Node.js + Express**: خادم بسيط، أمر تشغيل واحد (`npm start`)، بدون خطوات بناء (build) معقدة — مناسب لمستخدم غير مبرمج.
- **better-sqlite3**: قاعدة بيانات حقيقية بملف واحد (`data/alhadaf.db`)، لا تحتاج تثبيت سيرفر قاعدة بيانات منفصل، وسريعة ومتزامنة (synchronous API يبسّط الكود).
- **EJS**: قوالب HTML بسيطة تُصيَّر من السيرفر (server-rendered)، تدعم RTL والعربي بدون تعقيد أدوات بناء frontend حديثة.
- **express-session**: جلسة بسيطة بكوكي، تكفي لحماية بكلمة مرور واحدة (لا يوجد نظام مستخدمين متعدد).
- **json2csv**: تصدير Excel/CSV بدون مكتبات ثقيلة.
- **Chart.js** (مُوَرَّد محليًا في `public/js/chart.umd.min.js`، بدون CDN): رسوم بيانية في اللوحة الرئيسية.
- **خط Tajawal** مُنزَّل محليًا في `public/fonts/` (وليس عبر Google Fonts CDN) — درس مستفاد من مشروع سابق (`CLAUDE_CODE_HANDOFF.md`) أن خطوط النظام لا تشكّل العربي بشكل موثوق.

## نموذج البيانات (customers)

الحقول الإلزامية: `customer_name, national_id (10 أرقام), sale_date, payment_method, car_type, vin (17 خانة فريد), estimara_number (فريد)`.
حقول إضافية: `phone (05xxxxxxxx), salesperson, price, notes, status, delivery_at`.
حقول تتبّع: `reported/reported_at` (تبليغ المبيعات), `followup_done/followup_result/followup_note/followup_at` (متابعة ما بعد البيع), `is_demo` (لتمييز بيانات التجربة).

جدول `contact_log` منفصل (علاقة واحد-لمتعدد مع customers) لتسجيل كل مكالمة/زيارة/رسالة — هذا يغطي متطلب "العمليات والإجراءات" الموثقة رسميًا في معيار CRM.

## منطق التذكيرات (server/lib/util.js)

- **تذكير المتابعة**: `delivery_at + 24 ساعة`، يظهر في لوحة "مستحقات اليوم" ما دام `followup_done = 0`.
- **موعد تبليغ المبيعات**: نهاية الشهر التالي لشهر `sale_date` (مثال: بيع في يونيو → الموعد 31 يوليو). يتحول لونه أحمر (متأخر) لو فات الموعد ولم يُبلَّغ، وأصفر لو باقي أسبوع أو أقل.

## نقاط مهمة لأي جلسة قادمة

- المصادقة كلمة مرور واحدة فقط من `.env` (`APP_PASSWORD`) — لا يوجد نظام مستخدمين/صلاحيات متعددة، لأن المالك طلب بساطة صريحة ("أنا مو مبرمج... لا تسألني عن قرارات تقنية").
- استعادة النسخة الاحتياطية (`POST /data/restore`) **تحذف كل البيانات الحالية وتستبدلها بالكامل** — هذا سلوك مقصود حسب الطلب، ومُحذَّر منه بوضوح في الواجهة.
- التصدير (`GET /data/export.csv`) يحترم نفس فلاتر صفحة العملاء (بحث/طرق دفع/بائع/شهر/حالة) عبر تمرير نفس query params.
- ملف `data/alhadaf.db` وملف `.env` غير مرفوعين على git (`.gitignore`) — أي جلسة جديدة تحتاج `cp .env.example .env` قبل التشغيل.
- لا يوجد اختبارات آلية (unit/e2e) — تم التحقق يدويًا عبر curl + Playwright screenshots أثناء البناء (راجع سجل المحادثة إن احتجت إعادة الفحص).

## أوامر مفيدة

```bash
npm install        # تثبيت المكتبات (مرة واحدة)
npm start           # تشغيل السيرفر على المنفذ 3000 (أو PORT من .env)
npm run seed        # إضافة 4 عملاء تجريبيين + سجل تواصل
npm run clear-demo  # حذف البيانات التجريبية فقط (is_demo=1)
```
